# Diccionario de datos

Sistema para Venta de Computadoras. Motor: PostgreSQL.

Los nombres, tipos y restricciones coinciden con `database/01_ddl.sql`. Todos los campos son `NOT NULL`. Los importes usan `NUMERIC(10,2)`, que admite hasta 99 999 999.99. No se utiliza `FLOAT`.

## proveedores

Empresa que abastece productos.

| Campo | Tipo | Nulo | Restricciones | Descripción |
| --- | --- | --- | --- | --- |
| id_proveedor | INTEGER | No | PK. `GENERATED BY DEFAULT AS IDENTITY` | Identificador del proveedor |
| nombre | VARCHAR(120) | No | `chk_proveedores_nombre`: no puede quedar en blanco | Nombre o razón social |
| telefono | VARCHAR(20) | No | `chk_proveedores_telefono`: no puede quedar en blanco | Teléfono de contacto. Se guarda como texto para conservar el guion o el código de ciudad |
| correo | VARCHAR(120) | No | `uq_proveedores_correo`. `chk_proveedores_correo`: formato básico de correo | Correo de contacto. No se repite entre proveedores |

## productos

Artículo ofrecido por la tienda.

| Campo | Tipo | Nulo | Restricciones | Descripción |
| --- | --- | --- | --- | --- |
| id_producto | INTEGER | No | PK. `GENERATED BY DEFAULT AS IDENTITY` | Identificador del producto |
| nombre | VARCHAR(150) | No | `chk_productos_nombre`: no puede quedar en blanco | Nombre comercial |
| marca | VARCHAR(80) | No | `chk_productos_marca`: no puede quedar en blanco | Marca |
| categoria | VARCHAR(80) | No | `chk_productos_categoria`: no puede quedar en blanco | Categoría, por ejemplo Laptop, Monitor o Periferico |
| precio | NUMERIC(10,2) | No | `chk_productos_precio`: precio > 0 | Precio vigente de venta |
| stock | INTEGER | No | `chk_productos_stock`: stock >= 0 | Unidades disponibles después de las ventas registradas |
| id_proveedor | INTEGER | No | FK `fk_productos_proveedor` → `proveedores.id_proveedor`. `ON UPDATE CASCADE ON DELETE RESTRICT`. Índice `idx_productos_id_proveedor` | Proveedor del producto |

## clientes

Persona que puede realizar compras.

| Campo | Tipo | Nulo | Restricciones | Descripción |
| --- | --- | --- | --- | --- |
| id_cliente | INTEGER | No | PK. `GENERATED BY DEFAULT AS IDENTITY` | Identificador del cliente |
| nombre | VARCHAR(150) | No | `chk_clientes_nombre`: no puede quedar en blanco | Nombre del cliente |
| documento | VARCHAR(20) | No | `uq_clientes_documento`. `chk_clientes_documento`: de 8 a 12 dígitos | Documento de identidad. En los datos de prueba se usan DNI de 8 dígitos |
| telefono | VARCHAR(20) | No | `chk_clientes_telefono`: no puede quedar en blanco | Teléfono de contacto |

## ventas

Cabecera de una venta.

| Campo | Tipo | Nulo | Restricciones | Descripción |
| --- | --- | --- | --- | --- |
| id_venta | INTEGER | No | PK. `GENERATED BY DEFAULT AS IDENTITY` | Identificador de la venta |
| id_cliente | INTEGER | No | FK `fk_ventas_cliente` → `clientes.id_cliente`. `ON UPDATE CASCADE ON DELETE RESTRICT`. Índice `idx_ventas_id_cliente` | Cliente de la venta |
| fecha | TIMESTAMP | No | Valor por defecto `CURRENT_TIMESTAMP` | Fecha y hora local del registro, sin zona horaria |
| total | NUMERIC(10,2) | No | `chk_ventas_total`: total >= 0 | Suma de los subtotales. La API lo calcula dentro de la transacción antes de confirmar |

## detalle_venta

Línea de una venta.

| Campo | Tipo | Nulo | Restricciones | Descripción |
| --- | --- | --- | --- | --- |
| id_detalle | INTEGER | No | PK. `GENERATED BY DEFAULT AS IDENTITY` | Identificador de la línea |
| id_venta | INTEGER | No | FK `fk_detalle_venta_venta` → `ventas.id_venta`. `ON UPDATE CASCADE ON DELETE RESTRICT`. Índice `idx_detalle_venta_id_venta` | Venta a la que pertenece la línea |
| id_producto | INTEGER | No | FK `fk_detalle_venta_producto` → `productos.id_producto`. `ON UPDATE CASCADE ON DELETE RESTRICT`. Índice `idx_detalle_venta_id_producto` | Producto vendido |
| cantidad | INTEGER | No | `chk_detalle_cantidad`: cantidad > 0 | Unidades vendidas |
| precio_unitario | NUMERIC(10,2) | No | `chk_detalle_precio`: precio_unitario > 0 | Precio tomado del producto en el momento de la venta |
| subtotal | NUMERIC(10,2) | No | `chk_detalle_subtotal`: subtotal = cantidad × precio_unitario | Importe de la línea |

La restricción `uq_detalle_venta_producto` hace única la pareja `(id_venta, id_producto)`.

## Integridad referencial

| Restricción | Tabla | Referencia | Al actualizar | Al borrar |
| --- | --- | --- | --- | --- |
| fk_productos_proveedor | productos | proveedores.id_proveedor | CASCADE | RESTRICT |
| fk_ventas_cliente | ventas | clientes.id_cliente | CASCADE | RESTRICT |
| fk_detalle_venta_venta | detalle_venta | ventas.id_venta | CASCADE | RESTRICT |
| fk_detalle_venta_producto | detalle_venta | productos.id_producto | CASCADE | RESTRICT |

`ON UPDATE CASCADE` mantiene las referencias si alguna clave primaria cambiara. `ON DELETE RESTRICT` impide borrar un registro que todavía está siendo usado. La API de este proyecto no expone operaciones de borrado.
